# Серверная часть: аккаунт родителя и перенос прогресса

> Фича-спека. Версия 0.2 от 2026-11-11: сервер — Neon Postgres и Vercel Functions вместо Supabase (5.1). Общие принципы — в [SPEC.md](../SPEC.md) 7.1 (сервер), 3.9–3.10 (родительская зона и настройки), 11.7 (подписка и промокоды). Здесь — подробности, по которым можно делать.

## 1. Что это

Облачная копия прогресса ребёнка под аккаунтом родителя. Ребёнок играет как сейчас, всё хранится на устройстве; если родитель вошёл в аккаунт, приложение в фоне копирует прогресс на сервер и забирает его оттуда на любом другом устройстве, где выполнен тот же вход.

Что это даёт:
- **Новый планшет, переустановка, потерянный телефон** — стикеры, альбомы, монеты и дорожка уроков возвращаются после входа.
- **Несколько устройств в семье** — планшет дома и телефон в дороге показывают одного и того же ребёнка с одним прогрессом.
- **Подписка следует за семьёй** — право `premium` привязано к аккаунту, а не к устройству (11.7).
- **До 4 детей в аккаунте** — у каждого свой прогресс, профили видны на всех устройствах семьи.

Чего это **не** делает:
- не требует аккаунта: без входа приложение работает полностью, как сегодня;
- не хранит ничего о ребёнке, кроме игрового прогресса; имя ребёнка остаётся на устройстве;
- не даёт многопользовательской игры в реальном времени: два устройства не видят изменения друг друга мгновенно, только при очередной синхронизации.

Принцип, от которого всё остальное: **устройство — источник правды, облако — копия.** Все экраны читают и пишут локальное состояние, как сейчас. Синхронизация — отдельный модуль, который наблюдает за локальным состоянием и не блокирует ни одно действие ребёнка.

## 2. Где встречается

Ребёнок этой фичи не видит. Всё — в родительской зоне, за родительским замком.

| Где | Что добавляется |
|---|---|
| Родительская зона → Settings | Блок «Аккаунт» вверху вкладки: вход, состояние синхронизации, выход, удаление аккаунта (см. 3) |
| Родительская зона → Settings | Блок «Дети» (профили): список, добавить, переключить, удалить (см. 4.6) |

| Экран «Открыть всё» (11.7) | Промокод проверяется на том же сервере; «Восстановить покупку» использует идентификатор аккаунта |
| Testing | Кнопки «Sync now», «Show cloud doc», «Force conflict» (в релизе скрыть вместе со вкладкой) |

## 3. Экраны

Всё текстом, без озвучки: экраны для взрослого. Язык — язык инструкций из настроек (ru / en / uk).

### 3.1. Блок «Аккаунт», не выполнен вход

```
 ┌─ Аккаунт ───────────────────────────────────────────┐
 │ Войдите, чтобы сохранить прогресс и перенести его   │
 │ на другое устройство.                                │
 │                                                      │
 │ [  Sign in with Apple ]  [ G  Google ]  [ ✉ E-mail ] │
 └──────────────────────────────────────────────────────┘
```

- Три кнопки — три способа входа, паролей нет. На iOS Apple идёт первой (требование Apple, если есть любой сторонний вход), на Android первым Google.
- E-mail: поле адреса → «Отправить код» → поле для 6 цифр из письма. Код, а не ссылка: ссылка открывает браузер и теряет приложение, а код родитель переписывает с телефона.
- Пока вход идёт, кнопки неактивны, крутится индикатор. Ошибка сети — строка «Нет связи. Попробуйте позже» под кнопками, ничего больше не меняется.

### 3.2. Блок «Аккаунт», вход выполнен

```
 ┌─ Аккаунт ───────────────────────────────────────────┐
 │ mama@example.com                                     │
 │ ✓ Прогресс сохранён · сегодня 12:40                  │
 │                                                      │
 │ [ Выйти ]                        [ Удалить аккаунт ] │
 └──────────────────────────────────────────────────────┘
```

Строка состояния — одно из:
- «✓ Прогресс сохранён · сегодня 12:40» — последняя успешная запись в облако;
- «⟳ Сохраняем…» — идёт запись;
- «Нет связи · последнее сохранение вчера 19:05» — есть несохранённые изменения, сети нет; не ошибка, серым;
- «Нужно войти заново» + кнопка «Войти» — сессия отозвана (сменили пароль Apple ID, аккаунт удалён с другого устройства). Пока родитель не войдёт, устройство работает локально;
- «Обновите приложение, чтобы сохранять прогресс» — в облаке документ новее, чем понимает эта версия (см. 5.4).

Кнопки:
- **Выйти** — подтверждение: «Прогресс останется на этом устройстве, но перестанет сохраняться в облако». После выхода профили и прогресс на устройстве остаются; связь с аккаунтом разорвана.
- **Удалить аккаунт** — обязательна для App Store и Google Play. Подтверждение с вводом слова «УДАЛИТЬ»: «Удалим аккаунт и прогресс всех детей из облака. На этом устройстве прогресс останется. Подписка из магазина не отменяется — отмените её в настройках App Store / Google Play». Выполняется серверной функцией (6.2).

### 3.3. Экран «Нашли прогресс»

Показывается один раз сразу после входа, если **и в облаке, и на устройстве** есть непустой прогресс (см. 4.3, что считается пустым).

```
 ┌──────────────────────────────────────────────────────┐
 │ В аккаунте уже есть прогресс                          │
 │                                                      │
 │ ● В облаке:   32 слова · 14 стикеров · 3 альбома     │
 │               обновлено вчера, 19:05                  │
 │ ● На планшете: 8 слов · 2 стикера · 1 альбом         │
 │                                                      │
 │ [ Взять из облака ]   [ Оставить этот как нового     │
 │                         ребёнка ]                    │
 └──────────────────────────────────────────────────────┘
```

- **Взять из облака** — локальный прогресс заменяется облачным. Перед заменой локальная копия откладывается в `sticker-backup-<дата>` в хранилище устройства на 30 дней (на случай «ой, не то нажала»; кнопка восстановления — только во вкладке Testing, в 1.0 без интерфейса).
- **Оставить как нового ребёнка** — локальный прогресс становится ещё одним профилем аккаунта (если свободен слот из четырёх и есть право на профили, 4.6). Если слотов нет — кнопка неактивна с пояснением.
- Имя ребёнка в облаке нет, поэтому в строке «В облаке» пишем числа, а не имя. Если профилей в облаке несколько — список строк, по одной на профиль, выбор радиокнопкой.
- Счётчики: слова = ключи `stats.words` с числом > 0; стикеры = `bought` с числом > 0; альбомы = наборы, где куплен хотя бы один стикер.

Экран не показывается, если:
- на устройстве прогресс пустой — облако просто скачивается;
- в облаке пусто — локальный профиль отправляется как первый профиль аккаунта;
- это уже связанное устройство (повторный запуск) — обычная синхронизация.

## 4. Механика

### 4.1. Аккаунт

- Аккаунт — родительский, один на семью. Идентификатор — строка, которую выдаёт вход (Better Auth, 5.1); он же уходит в RevenueCat как `app_user_id` (11.7).
- Способы входа: Sign in with Apple, Google, e-mail с одноразовым кодом. Один и тот же e-mail через Apple и через код — один аккаунт (связывание по подтверждённому адресу; Apple «скрыть e-mail» даёт релейный адрес, он считается отдельным аккаунтом — предупредить на экране входа: «Чтобы прогресс нашёлся на другом устройстве, входите одним и тем же способом»).
- Сессия хранится на устройстве и обновляется сама (refresh token). Повторный вход нужен только если сессия отозвана.
- Ребёнок не видит ни входа, ни аккаунта. Все экраны этого раздела — за родительским замком.

### 4.2. Документ профиля

Один профиль ребёнка = один JSON-документ, несколько килобайт (верхняя оценка: 7 альбомов × 50 наклеек × 60 байт ≈ 20 КБ; лимит на сервере 256 КБ).

```
{
  "schema": 1,                 // версия формата документа (5.4)
  "coins": 37,
  "bought":   { "farm:cow": 1, ... },        // куплено всего, ключ стикера → штук
  "scenes":   { "farm": [ { "k": "farm:cow", "x": 410, "y": 220, "s": 1.2, "r": -8, "f": false, "z": 3 } ] },
  "rewarded": [ "farm" ],                    // наборы, за которые выдан кубок
  "prog":     { "main": { "0": "gold", "1": "ok" }, "lvl2": {} },
  "lvl2open": false,                         // родитель открыл уровень 2 досрочно
  "lastTrack": "main",
  "stats":    { "tasks": 120, "correct": 101, "wrong": 19, "puzzles": 9, "pairs": 7,
                "words": { "cow": 6 }, "letters": { "S": 4 }, "err": { "cow": 2 } },
  "time":     { "day": "2026-11-07", "usedMs": 480000 },
  "settings": { "lang": "ru", "musicVol": 50, "voiceVol": 100, "sfxVol": 100, "hints": true,
                "limit": 0, "parentWho": "mom", "parentAcc": "", "parentDat": "",
                "avatar": "farm:cow" }                  // картинка профиля на экране «Кто играет?» (startup.md 4.5)
}
```

Что **не** входит в документ и живёт только на устройстве:
- `kidName` — имя ребёнка (решение SPEC 3.10: в облаке нет персональных данных ребёнка);
- `inv` — стикеры на полке: вычисляется как `bought[k] − наклеено(k)`, хранить не нужно и нельзя (при слиянии разойдётся);
- `mute` — кнопка 🔇 у ребёнка, это про конкретное устройство;
- `limitSet`, `unlocked` и другие флаги миграций старых сохранений.

Текущий `S` (`web/js/state.js`) превращается в документ функцией `toDoc(S)` и обратно `fromDoc(doc, local)`, где `local` — локальные поля (имя, mute).

### 4.3. Пустой прогресс

Профиль считается **пустым**, если ничего не куплено (`bought` пуст), ни один урок не пройден (`prog` пуст по всем дорожкам) и `stats.tasks == 0`. Монеты не учитываются: стартовые 20 монет есть у любого нового профиля. Пустой профиль при входе молча заменяется облачным (3.3).

### 4.4. Когда синхронизируем

Синхронизация — только при выполненном входе. Без входа модуль спит.

**Загрузка (pull):**
- при запуске приложения и при возвращении из фона, если прошло больше 5 минут с прошлой загрузки;
- сразу после входа;
- при смене профиля.

**Запись (push):**
- при выходе с экрана результата урока;
- после покупки стикера;
- при выходе из альбома (наклейки) и из коллекции;
- при изменении настроек в родительской зоне;
- при уходе приложения в фон (`visibilitychange` / Capacitor `pause`);
- таймер «тихих» изменений: если что-то изменилось (например, минуты лимита), но событий выше не было — запись не чаще раза в минуту.

Каждое событие ставит флаг `dirty`; запись объединяет накопившиеся изменения в один запрос. Если сети нет — флаг остаётся, запись повторится при следующем событии или при появлении сети (`online`). Флаг хранится в localStorage, чтобы пережить закрытие приложения.

Запись и загрузка никогда не показывают индикаторов в детской части и не блокируют экран.

### 4.5. Версии и слияние

Документ на сервере носит `version` (целое, растёт на 1 при каждой записи) и `updated_at`. Устройство помнит `version` документа, от которого отталкивается (`baseVersion`).

**Запись:** устройство отправляет `(profile_id, baseVersion, doc)`. Сервер в одной транзакции:
- если `version` на сервере == `baseVersion` — записывает документ, `version += 1`, возвращает новую версию. Обычный случай: одно устройство за раз;
- иначе — **конфликт**: ничего не пишет, возвращает серверный документ и его `version`. Устройство сливает (ниже), подставляет новую `baseVersion` и повторяет запись. Повтор не больше 3 раз, затем ждём следующего события.

**Загрузка:** если серверная `version` больше `baseVersion` и локально `dirty` не стоит — просто принимаем серверный документ. Если `dirty` стоит — сливаем и записываем результат.

**Слияние** делается на устройстве (тот же JS, что и приложение; на сервере логики слияния нет). Поля объединяются по смыслу, а не «кто позже»:

| Поле | Правило | Почему |
|---|---|---|
| `prog` | объединение по урокам; `gold` сильнее `ok` | пройденное на любом устройстве — пройдено |
| `rewarded` | объединение | кубок не отнимается |
| `bought[k]` | максимум по каждому ключу | оба значения выросли из общей базы; сумма удвоила бы покупки |
| `stats.*` счётчики и `words/letters/err[k]` | максимум по ключу | та же причина; небольшая недооценка допустима, это статистика для родителя |
| `coins` | из документа с более поздним `updated_at` | складывать нельзя (удвоятся), разницу считать не из чего |
| `scenes` | по альбомам: для каждого альбома — версия из более позднего документа | наклейки двигают руками, объединять списки нельзя; поальбомно, чтобы альбом с планшета не затирал альбом с телефона |
| `settings`, `lvl2open`, `lastTrack` | из более позднего документа | настройки меняет один родитель |
| `time` | один день — максимум `usedMs`; разные дни — более поздний день | лимит общий на ребёнка, а не на устройство |
| `schema` | максимум | см. 5.4 |

После слияния `inv` пересчитывается: `inv[k] = max(0, bought[k] − наклеено(k) во всех альбомах)`.

Границы правила: слияние по полям — приближение для редкого случая «два устройства разошлись без сети». Потерять можно несколько монет или одну наклейку; нельзя потерять пройденный урок, купленный стикер или кубок. Этого достаточно для 1.0; журнал событий (точное слияние) — в открытых вопросах.

### 4.6. Профили (дети)

- В аккаунте до **4 профилей**; без права `premium` — 1 (проверка `isPremium()` на устройстве; сервер проверяет только «не больше 4»).
- `profile_id` — UUID, который создаёт устройство в момент создания профиля (до любого входа), так что локальный профиль можно отправить в облако без переименования.
- Локально у каждого профиля свой ключ хранения `sticker-profile-<id>`, плюс `sticker-local-<id>` для имени и mute. Текущий профиль — `sticker-current`. Старое сохранение `sticker-proto-v2` при первом запуске новой версии превращается в профиль 1 (миграция, 10).
- Блок «Дети» в родительской зоне: список «Маша · 32 слова», «Без имени · 0 слов»; текущий отмечен; «Добавить ребёнка» (имя, язык, обращение к взрослому); на профиле — «Переключить», «Переименовать», «Удалить».
- Удаление профиля — подтверждение «Стикеры и альбомы пропадут» и помечает документ на сервере `deleted_at` (не удаляет строку, 30 дней на восстановление через поддержку); на всех устройствах профиль исчезает при следующей загрузке. Удалить последний профиль нельзя.
- Имя ребёнка — на устройстве; на втором устройстве профили из облака появляются «Без имени», родитель вводит имя там. Это цена решения не хранить имя в облаке (SPEC 3.10); отмечено в открытых вопросах.
- Переключение профилей ребёнком — только на экране «Кто играет?» при запуске, с настройкой родителя (замок / не спрашивать); внутри игры переключателя нет, иначе дети тратят чужие монеты. Подробности и пересмотр прежнего решения — [startup.md](startup.md) 3.4–3.5, 4.6.

### 4.7. Подписка и промокоды

Описано в SPEC 11.7; здесь только связь с аккаунтом.
- До входа RevenueCat работает с анонимным идентификатором устройства. При входе — `Purchases.logIn(accountId)`: RevenueCat переносит покупки анонимного пользователя на аккаунт. При выходе — `logOut()`, право на устройстве остаётся в кэше на 7 дней (11.7).
- Промокод: серверная функция `POST /api/redeem` (6.1) принимает код под сессией аккаунта, проверяет таблицу кодов, просит RevenueCat выдать право `premium` этому `app_user_id`. Промокод без входа невозможен — на экране «Открыть всё» поле кода ведёт на вход, если его нет.

## 5. Данные и сервер

### 5.1. Технология

**Neon Postgres и Vercel Functions** (решено 2026-11-11). Прежнее решение — Supabase — отменено: у проекта уже есть Vercel Pro, и база, API и сайт живут в одном кабинете и на одном счёте. Плата за это — свой небольшой API и вход через библиотеку, которые Supabase давал готовыми.

- **База** — Neon Postgres, подключена к проекту `stick-and-speak` через Vercel Marketplace (Storage), регион Франкфурт (`aws-eu-central-1`) для GDPR. Счёт идёт через Vercel. Строку подключения `DATABASE_URL` ставит интеграция в переменные окружения проекта; в репозитории и в приложении её нет.
- **API** — Vercel Functions в том же проекте: файлы в `web/api/`, Node.js, регион `fra1` рядом с базой (`vercel.json`). Драйвер `@neondatabase/serverless`: запросы к базе по HTTP, без пула соединений, что подходит функциям.
- **Вход** — библиотека Better Auth внутри функций, её таблицы в той же базе. Способы: e-mail с кодом из 6 цифр (плагин email OTP), Google, Apple. На сайте сессия — cookie, в нативных приложениях — токен в заголовке (плагин bearer); нативный вход Google и Apple — Capacitor-плагин отдаёт `id_token`, Better Auth меняет его на сессию.
- **Письма с кодом** — Resend через Vercel Marketplace, бесплатного тарифа хватает. Это единственный сервис вне Vercel и Neon, и без него вход по e-mail невозможен.
- **Права проверяет API.** Приложение к базе напрямую не ходит. Каждая функция берёт аккаунт из сессии и подставляет его в запрос (`where account_id = $1`); чужие строки недостижимы.
- **Окружения.** Production — ветка Neon `main`. Development — ветка Neon `dev` (та же схема, свои данные), локально `vercel dev` на компьютере. Ветки Neon заменяют два отдельных проекта.
- **Объём.** Бесплатного тарифа Neon хватает на старте: при 20 КБ на профиль 0,5 ГБ — это около 25 тысяч профилей. Цены и пределы тарифов сверить перед выпуском.
- **Скорость.** Ребёнок облака не ждёт: запись идёт в фоне (4.4), при запуске приложение ждёт облако не дольше 2,5 с (startup.md 4.1). Запрос — одна функция во Франкфурте и база рядом. База на бесплатном тарифе засыпает без запросов, первый запрос после сна медленнее на доли секунды; это укладывается в 2,5 с.

### 5.2. Таблицы

```sql
-- таблицы входа ("user", session, account, verification) создаёт Better Auth; своей таблицы аккаунтов нет

create table profiles (
  id          uuid primary key,                          -- profile_id, создаёт устройство
  account_id  text not null references "user"(id) on delete cascade,
  version     integer not null default 0,
  schema      integer not null default 1,
  state       jsonb   not null check (pg_column_size(state) <= 262144),   -- документ 4.2, не больше 256 КБ
  device_id   text,                                      -- случайный UUID устройства, не серийник
  updated_at  timestamptz not null default now(),
  created_at  timestamptz not null default now(),
  deleted_at  timestamptz
);
create index on profiles (account_id);

create table promo_codes (
  code        text primary key,                          -- 'FRIENDS-2026-A1B2'
  kind        text not null,                             -- friends | partner | promo
  days        integer,                                   -- срок права; null = бессрочно
  max_uses    integer not null default 1,
  used        integer not null default 0,
  expires_at  timestamptz,
  note        text
);
create table promo_redemptions (
  code        text references promo_codes(code),
  account_id  text references "user"(id) on delete cascade,
  redeemed_at timestamptz default now(),
  primary key (code, account_id)                         -- один код — один раз на аккаунт
);
```

Правила доступа (проверяет API, 5.1):
- `profiles`: каждая функция читает и пишет только строки, где `account_id` — аккаунт из сессии; вставка — не больше 4 живых профилей на аккаунт (триггер в базе как страховка); `state` не больше 256 КБ (проверка в API до запроса и `check` в базе); `version` меняется только записью из 5.3.
- `promo_codes`, `promo_redemptions`: из приложения недоступны; с ними работает только функция `/api/redeem`.

### 5.3. API и запись с проверкой версии

Все запросы — под сессией родителя; без сессии ответ 401. Тела и ответы — JSON.

| Запрос | Что делает |
|---|---|
| `GET /api/profiles` | Все живые профили аккаунта: `id, version, schema, state, updated_at` (`deleted_at is null`) |
| `PUT /api/profiles/<id>` | Запись с проверкой версии, тело `{ base, state, schema, device }` (ниже) |
| `DELETE /api/profiles/<id>` | Ставит `deleted_at` (4.6); строку не удаляет |
| `POST /api/redeem` | Промокод (6.1) |
| `POST /api/account/delete` | Удаление аккаунта (6.2) |
| `/api/auth/*` | Вход, выход, обновление сессии — обработчик Better Auth |

Запись `PUT /api/profiles/<id>` — один SQL-запрос:
- Если профиля нет — создаёт его с владельцем из сессии, `version = 1`; ответ `{ ok: true, version: 1 }`.
- Если `version = base` и профиль этого аккаунта — обновляет `state`, `schema`, `device_id`, `updated_at`, `version + 1`; ответ `{ ok: true, version }`.
- Иначе — `{ ok: false, version, state, schema }`: текущий документ для слияния на устройстве.
- Профиль другого аккаунта — 404, будто его нет: не раскрываем, что такой `id` существует.

Запрос записи в SQL (`$acc` — аккаунт из сессии):
```sql
insert into profiles (id, account_id, version, schema, state, device_id)
values ($id, $acc, 1, $schema, $state, $device)
on conflict (id) do update
  set state = excluded.state, schema = excluded.schema, device_id = excluded.device_id,
      updated_at = now(), version = profiles.version + 1
  where profiles.account_id = $acc and profiles.version = $base
returning version;
-- нет строки в ответе → прочитать текущий профиль этого аккаунта и вернуть ok: false (или 404)
```

- API принимает запросы с сайта и из нативных приложений: CORS разрешает `https://stick-and-speak.vercel.app`, `capacitor://localhost` (iOS) и `https://localhost` (Android).
- Офлайн-кэш (`web/sw.js`) запросы `/api/` не трогает: прогресс из облака не должен приходить из кэша.

### 5.4. Версии формата документа

- `schema` — номер формата документа. Приложение знает свой `SCHEMA`. Миграции старых документов — те же функции, что сейчас чинят старые сохранения при запуске (переименованные стикеры, альбомы meadow → farm), оформленные как список «с версии N на N+1».
- Документ со `schema` ≤ `SCHEMA` приложение мигрирует при загрузке и пишет обратно уже в своём формате.
- Документ со `schema` > `SCHEMA` (на другом устройстве приложение новее) — приложение его **не записывает**: работает локально с тем, что было, в родительской зоне строка «Обновите приложение, чтобы сохранять прогресс». Читать такой документ тоже не пытаемся: неизвестные поля могли изменить смысл известных.
- Контент (список стикеров, уроков) не хранится в документе, только ссылки по ключам; стикер, которого в этой версии нет, при загрузке отбрасывается, как сейчас.

### 5.5. Безопасность и приватность

- В облаке **нет персональных данных ребёнка**: ни имени, ни возраста, ни фото, ни голоса. Есть e-mail родителя (взрослого) и игровой прогресс. Это держит нас в COPPA / GDPR-K и в анкетах детской категории магазинов.
- Идентификатор устройства — случайный UUID, создаётся приложением; серийники, рекламные идентификаторы не читаем.
- Все запросы под сессией родителя; без сессии API отвечает 401. Ключей базы в приложении нет: строка подключения только в переменных окружения Vercel. Вход ограничивает частоту попыток (встроенный лимит Better Auth), код из письма живёт 10 минут.
- Логи функций — без тела документов и без кодов из писем; хранятся столько, сколько держит Vercel по тарифу.
- Регион данных — ЕС (Франкфурт): база и функции. Это надо написать в политике приватности вместе с перечнем полей из 4.2. Обработчики данных: Vercel, Neon, Resend (только e-mail родителя).
- Удаление аккаунта удаляет всё за одну операцию (`on delete cascade`). История восстановления Neon (откат базы на момент времени) хранит данные столько, сколько даёт тариф; фактический срок указать в политике.
- Экспорт данных по запросу (GDPR) — документы профилей в JSON; в 1.0 вручную через поддержку.

### 5.6. Ошибки и пределы

| Ситуация | Поведение |
|---|---|
| Нет сети | Молча; флаг `dirty` остаётся; строка состояния в родительской зоне |
| 401 / сессия отозвана | Локальный режим; «Нужно войти заново» в родительской зоне; ребёнок ничего не замечает |
| Конфликт версий | Слияние и повтор, до 3 раз |
| Документ > 256 КБ | Сервер отвергает; приложение пишет в консоль и не повторяет до следующего изменения (в норме недостижимо) |
| Пятый профиль | Сервер отвергает; интерфейс до этого не допускает |
| Сервер недоступен (5xx) | Как «нет сети», повтор с удвоением паузы: 1, 2, 4… до 10 минут |

## 6. Серверные функции (Vercel Functions)

### 6.1. `POST /api/redeem`

Тело: `{ code }`, сессия аккаунта обязательна. Шаги: нормализовать код (верхний регистр, без пробелов и дефисов) → найти в `promo_codes` → проверить `expires_at`, `used < max_uses`, нет записи в `promo_redemptions` для этого аккаунта → записать активацию, `used + 1` → RevenueCat REST «grant promotional entitlement» `premium` на `days` (или бессрочно) для `app_user_id = account_id` → ответ `{ ok, until }`. Ошибки: `not_found`, `expired`, `exhausted`, `already_used` — приложение показывает текст по коду ошибки.

### 6.2. `POST /api/account/delete`

Сессия аккаунта обязательна. Удаляет пользователя из таблицы `"user"` Better Auth (профили, сессии, способы входа и активации промокодов — каскадом), вызывает RevenueCat «delete subscriber» для `app_user_id`. Ответ `{ ok }`. После ответа приложение чистит сессию и остаётся в локальном режиме.

### 6.3. Что намеренно не делаем

- Нет серверной проверки «премиум ли аккаунт» для второго профиля: право живёт в RevenueCat и на устройстве; сервер ограничивает только 4.
- Нет вебхуков RevenueCat: состояние подписки приложение берёт из SDK.
- Нет пуш-уведомлений, нет аналитики на сервере.

## 7. Голос

Новых реплик нет. Все экраны фичи — текстовые, для взрослого, за родительским замком; переводятся на три языка инструкций вместе с остальным текстом родительской зоны.

## 8. Открытые вопросы

1. **Имя ребёнка на втором устройстве.** Профили приходят «Без имени», родитель вводит заново — при входе с первого экрана это шаг «Кто эти дети?» (startup.md 3.3), иначе блок «Дети»; на карточках «Кто играет?» ребёнка выручает аватар, он синхронизируется (startup.md 4.5). Альтернатива — хранить имя в облаке с согласия родителя (галочка «Запомнить имя в аккаунте»): это уже персональные данные ребёнка и анкета для магазинов сложнее. Пока — без имени.
2. **Точность слияния монет.** Правило «из более позднего документа» может потерять монеты, если два устройства одновременно были без сети. Точное решение — журнал событий (заработал / потратил) вместо числа; оставляем на потом, если появятся жалобы.
3. **Apple «скрыть e-mail».** Релейный адрес Apple и настоящий адрес через Google — два разных аккаунта. Предупреждение на экране входа достаточно? Или дать «связать способы входа» в настройках аккаунта.
4. **Лимит времени на двух устройствах.** Берём максимум `usedMs` за день, а не сумму: если ребёнок играл по 10 минут на двух устройствах без сети, лимит увидит 10, а не 20. Приемлемо для 1.0.
5. **Семейный доступ без аккаунта** (код переноса из SPEC 7.1) — не в 1.0; схема документа та же.
6. **Вход на сайте** для Stripe (11.3.2) — тот же аккаунт и тот же вход (Better Auth на том же домене); когда дойдём до сайта.
7. **Better Auth в нативных приложениях.** Вход Google и Apple в Capacitor через `id_token` — главный риск выбора. Проверить пробой на Android и iOS до остальной работы (TASKS 2.6б). Если не заработает — запасной вариант Auth.js или свой обмен `id_token` на сессию в функции (проверка подписи токена Google и Apple).

## 9. Объём для 1.0

Входит: вход тремя способами, документ профиля, pull/push, слияние, экран «Нашли прогресс», до 4 профилей, выход, удаление аккаунта, `/api/redeem`, `/api/account/delete`, миграция старого сохранения в профиль 1.

Не входит: журнал событий, код переноса без аккаунта, восстановление удалённого профиля из интерфейса, экспорт данных из приложения.

## 10. Реализация

- **Код приложения:** новый модуль `web/js/cloud.js` (и `web/js/profiles.js` для профилей): `Cloud.init()`, `Cloud.signIn(provider)`, `Cloud.signOut()`, `Cloud.pull()`, `Cloud.push()`, `Cloud.markDirty()`, `mergeDoc(local, remote)`, `toDoc(S)` / `fromDoc(doc)`; профили — `Profiles.list/create/switch/remove`, ключи localStorage из 4.6. Вызовы `markDirty()` — в точках из 4.4 (`lessonDone`, покупка, выход из альбома, настройки). Функция `save()` остаётся локальной и синхронной, как сейчас.
- **Библиотеки в приложении:** нет. `cloud.js` вызывает `/api/` через `fetch`, вход — через HTTP-запросы к `/api/auth/*`; сборщика нет, как и во всём приложении. Вход Apple и Google нативно — Capacitor-плагин (`@capgo/capacitor-social-login` или пара плагинов Apple + Google), его `id_token` уходит в Better Auth; в браузере на компьютере — обычный OAuth-переход, чтобы фичу можно было проверять без телефона (SPEC 7.2).
- **Сервер:** функции в `web/api/` (`profiles/[id].js`, `profiles/index.js`, `redeem.js`, `account/delete.js`, `auth/[...all].js`, общие `_db.js` и `_auth.js`), зависимости в `web/package.json` (`@neondatabase/serverless`, `better-auth`), регион и функции в `web/vercel.json`. Схема — `server/schema.sql` и миграции Better Auth; `server/README.md` — переменные окружения, ветки Neon, как применить схему и развернуть. Секреты (`DATABASE_URL`, `BETTER_AUTH_SECRET`, ключи Google, Apple, Resend, RevenueCat) — только в переменных окружения Vercel.
- **Сборка нативных приложений:** `app/build.sh` не копирует в приложение `api/`, `package.json`, `node_modules` и `vercel.json`. Адрес API — константа `API_BASE`: на сайте пустая (тот же домен), в нативной сборке `https://stick-and-speak.vercel.app`.
- **Миграция:** при первом запуске версии с профилями `sticker-proto-v2` переносится в `sticker-profile-<uuid>` и `sticker-current`; старый ключ не удаляется ещё одну версию.
- **Проверка в браузере:** вкладка Testing — «Sync now», «Show cloud doc», «Force conflict» (ставит `baseVersion − 1` и пишет: должны увидеть слияние). Сценарии для ручной проверки: два окна браузера с одним аккаунтом; офлайн-режим в DevTools; выход и вход; удаление аккаунта на `dev`.
- **Политика приватности и анкеты магазинов** — обновить списком полей из 4.2 и регионом хранения (5.5).
